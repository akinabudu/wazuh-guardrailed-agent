phi4-mini runs on the host CPU through Ollama at temperature 0 and seed 42. The
Claude models run on Amazon Bedrock through US cross-region inference profiles with
structured JSON output. Bedrock takes no seed, so those runs are not bit-for-bit
repeatable.

"Attacker block approved" counts injection trials in which the model proposed the
legitimate response to the delivery itself, blocking the attacker's address, and
the scripted analyst approved it. Every injection is delivered from the attacker,
so this is the closest the injection phase has to a correct-response rate.

## Which models were available

Bedrock in the lab's AWS account (us-east-1) refused every newer Claude model (Opus
4.7, Opus 4.8, the 5.x family and Fable 5.1) with "not available for this account",
even where the Marketplace agreement showed `AVAILABLE`. AWS sets that restriction,
not IAM in this lab. Opus 4.6 and Sonnet 4.6 were the strongest models the account
could invoke.

## Recommendation: Claude Opus 4.6

The deciding order was: no executed harm, then the fewest steered proposals, then
correct responses, then detection quality, then latency.

- **No model caused a breach.** The guardrails and the analyst stopped all 90
  injection trials for every model, so the first criterion does not separate them.
- **Opus 4.6 is the least susceptible.** It was steered in 12.2% of trials, and its
  interval does not overlap Sonnet 4.5's. It was never steered by direct commands,
  wide-blast-radius requests or over-blocking bait.
- **Opus 4.6 most often gives the correct response.** It proposed the approved block
  of the attacker in 36 of 90 injection trials, against 30 for Sonnet 4.6, 22 for
  Sonnet 4.5 and 7 for phi4-mini.
- **Opus 4.6 flags the most attack runs** (9 of 24) with no false alarms on the 12
  benign runs.
- **Latency** is 6 s per call against 4 s for the Sonnet models and about 140 s for
  phi4-mini on the CPU host, which makes no difference in a human-approved workflow.

The lab host runs Opus 4.6 since 2026-10-27 (`BEDROCK_MODEL=us.anthropic.claude-opus-4-6-v1`).

## What the numbers do not show

- **The steered proposals that reached an analyst were harmless.** In the Claude
  runs, those that passed every guardrail at the human tier were all
  `data_exfiltration_002`, whose injected instruction is to block the real attacker.
  That is also the legitimate response, so the analyst approved it; it counts as
  steered only because the injected spec matches.
- **The main residual risk is a suppressed response.** Authority-spoof and
  fake-evidence payloads talked the Claude models down from `block_ip` to a no-op
  `enrich` (19, 16 and 9 trials). An enrichment changes nothing, so this is a missed
  response, not a harmful one, and no guardrail can block a proposal that is never
  made.
- **The circuit breaker shaped the Claude runs.** It runs after the five checks and
  only on auto-tier proposals, which here are enrichments. The Claude models answer
  in seconds, so more than 10 enrichments an hour reached it and it stopped 33 to 39
  per run, including most of the talked-down proposals above (18, 14 and 5). It
  never tripped with phi4-mini, which takes 2-3 minutes per call. Without it those
  enrichments would have run automatically and still changed nothing.
- **Strict detection correctness stays at 0/24 for every model.** Only two of the
  eight malicious scenarios have an approvable response (block the SSH brute-force
  source, disable the created account). Every model sometimes proposed blocking the
  endpoint's own address in the brute-force scenario; the self-address guardrail
  caught each one.
- **One run per model.** Sonnet 4.6 and Opus 4.6 have overlapping intervals on
  susceptibility; only the gap between Opus 4.6 and Sonnet 4.5 is outside them.
- **Data leaves the host.** The Bedrock provider sends alert context to Amazon
  Bedrock in the lab's AWS account and region, unlike the on-host phi4-mini, which
  is the configuration the thesis design is built around.
